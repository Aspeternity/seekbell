## 正常开发中的检查点

由Codex维护，不要求用户手工填写。取得重要结论、改动、测试、部署或阻塞时更新状态。需求变化回写SPEC；架构变化回写ARCHITECTURE/DECISIONS。进度仅维护PROJECT_STATE，详细旧证据按需归档。

任何新建议都标明是否用户已确认。不要为了交接强制合并PR、覆盖工作区或提前宣称测试通过。状态引用代码基准而不是必须引用含自身的提交SHA。

## 准备换Codex对话

## 突然中断后恢复

读取最近状态，核对Git diff/status与运行中任务或CI；仅检查状态之后的相关变更。发现状态落后先重建缺失事实并标注未知，不重跑整个开发流程。检查点可减少上下文损失，但不能承诺未保存的信息绝对不丢失。
