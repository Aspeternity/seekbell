# Codex 启动与对话交接指令

## 首次开发

将规格包中的AGENTS.md、README.md和docs目录放到项目根目录；不要把压缩包当应用部署，不需先启动Docker。如果已有同名文件，比较合并而不是覆盖。

复制下面这段给Codex：

> 请开始SeekBell开发。先读取根目录AGENTS.md和docs/PROJECT_STATE.md，核对实际工作目录、操作系统、Git分支/提交/工作区，保留已有修改。按状态文件的“本任务需要读取”清单了解相关规格，然后开始M0工程初始化，不要只复述计划。遵守已确认范围和技术栈；缺少远程仓库、SSH或通知凭据时先完成本地开发和模拟验证。每个有意义的检查点更新PROJECT_STATE；区分已实现、自动测试、真实验证和用户验收。不要默认每次重读全部文档。需要远程操作时按已有授权执行，缺少授权则针对具体可审阅动作询问。

## 正常开发中的检查点

由Codex维护，不要求用户手工填写。取得重要结论、改动、测试、部署或阻塞时更新状态。需求变化回写SPEC；架构变化回写ARCHITECTURE/DECISIONS。进度仅维护PROJECT_STATE，详细旧证据按需归档。

任何新建议都标明是否用户已确认。不要为了交接强制合并PR、覆盖工作区或提前宣称测试通过。状态引用代码基准而不是必须引用含自身的提交SHA。

## 准备换Codex对话

> 请做SeekBell交接：运行`python3 scripts/dev_status.py`核对现状，按PROJECT_STATE固定分段更新进行中、未提交改动、证据位置、已排除路线、编号下一步、授权和按需读取。必要时归档已完成细节。不要为交接强行提交/合并或额外发布。最后给我一段简短的新对话启动文字。

## 新Codex对话继续

> 继续SeekBell开发。先运行`python3 scripts/dev_status.py`，再读AGENTS.md和docs/PROJECT_STATE.md，按状态文件“按需读取”补读与本任务相关的章节。不要默认重读所有文档或重跑全部测试。区分实现、测试与用户验收，沿用已记录且适用的授权，从下一具体步骤继续；状态不一致先核实，不覆盖已有工作。

## 顾问新对话继续

先向顾问提供最新PROJECT_STATE文件或其完整短摘要，以及本次问题相关的差异/日志/测试结果。顾问不一定能读取Codex工作区或私有仓库；不要假设聊天记忆自动同步。

> 继续担任SeekBell开发顾问。附上最新PROJECT_STATE及本次问题材料。请以当前代码与证据为准，按需索取具体章节，不重新全量审查项目。建议经我确认后，由Codex更新对应规格和状态。

## 突然中断后恢复

读取最近状态，核对Git diff/status与运行中任务或CI；仅检查状态之后的相关变更。发现状态落后先重建缺失事实并标注未知，不重跑整个开发流程。检查点可减少上下文损失，但不能承诺未保存的信息绝对不丢失。
