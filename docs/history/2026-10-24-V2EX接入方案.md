## 建议结论与范围

采用“官方匿名API V1新主题列表＋独立节点目录缓存＋官方热门列表”。不增加登录、Token、Cookie、浏览器、curl_cffi、第三方转发或额外运行服务，不访问主题详情/回复/会员详情，不建设公开内容镜像。这里需要明确批准：V2EX的主监控来源由RSS-only扩展为固定官方只读API；界面标注“官方公开API”，正文区域为最多2000字符的“接口内容摘录”，不假称RSS摘要或完整正文监控。官方API公平使用说明对将数据用于商业/个人网站内容填充提出限制，私有监控是否被允许不能仅凭匿名可访问认定；正式采用前应核对提供方使用要求，尤其是保存与对外展示，不以技术可访问代替许可。

节点仍仅在任务内配置，各网站独立，不增加网站级节点总范围；仅覆盖匿名接口实际输出的公开主题，不保证目录中每个节点都在最新列表输出，更不承诺权限主题、全站完整或零漏帖。

官方资料：

- API V1说明（Livid）：https://www.v2ex.com/p/7v9TEc53，说明最新/最热主题匿名GET及公平使用。
- 当前API 2.0说明：https://www.v2ex.com/help/api，需要Personal Access Token；本方案不接。
- 固定目录实源：https://www.v2ex.com/api/nodes/all.json。

在SeekBell-Dev、现有HTTPX、HTTP/1.1、无Cookie/令牌/代理/重定向的少量一次性读取中：
- index.xml：200、application/atom+xml、Atom根，50项均有作者/发布时间，作者资料URI与name一致；tags为0，没有独立节点字段。现有parse_rss及MIME白名单仅RSS 2.0，不能只换URL；不从标题或正文链接猜节点。
- topics/latest.json：200、本次36项，包含id/title/created/member.username/node.id/name/title等，按created降序；36项均在本次Atom50项中。两者窗口不同，此为时点证据，不能固定36/50或宣称接口覆盖全部节点。
- topics/hot.json：200、本次10项，带用户名/节点/回复数；不是完整的“每日/每周”周期承诺。
- nodes/all.json：200、本次1378项、794366字节，都有稳定id/name/title。
- index.json：404，不作为全站JSON Feed或备用入口。
- API实测限额头为600，但旧V1说明写120、当前V2说明写600；实际以有效响应头/等待指令与保守本地预算为准。目录的reset头出现过去时间，不能让缓存旧头放宽当前限流。
- API Cache-Control实测max-age=432000，但最新内容仍较新；Atom为300秒。不能据此把采集改成5天，也不能把某帖created/last_touched当作源站更新时间。

只保存字段/计数/响应头等研究元数据，私有目录acceptance/2026-10-24-v2ex-proposal下anonymous-source-probe.json、coverage-metadata-probe.json、json-feed-probe.json；无帖子正文、用户名样本或真实数据库入Git。一次200不代表长期/部署环境可用。

## 端点、频率与隔离

统一固定HTTPS主机www.v2ex.com，不让用户输入地址或自动切镜像域名。

|用途|固定路径|工程建议|
|---|---|---|
|新主题监控|/api/topics/latest.json|默认120秒、最小60秒；全部任务共享一份采集|
|节点目录|/api/nodes/all.json|成功快照持久化，24小时按需刷新，手动刷新10分钟冷却|
|社区热榜|/api/topics/hot.json|600秒按需缓存；无消费者不专门轮询|

频率是候选工程设置，不是官方时效/限流保证。采集、人工连接测试、目录与热榜共用V2EX站级单请求锁/至少2秒间隔/持久等待与额度预算；人工测试至少60秒冷却，真实发出才消耗配额，不直接采集、变更基线或发送。额度紧张优先保证采集，目录/热榜延期而非挤占采集；等待不伪造成来源失败。429遵守Retry-After及有效Reset，403/挑战按5→10分钟退避，网络/5xx按30秒→5分钟；禁止通过手测/刷新跳过服务器或额度等待。CDN的过期窗口/旧额度头不授予更多配额；本地预算保守计数，不假设同出口只有SeekBell。

现有WebsiteRequestBudget硬编码linuxdo，需改成按站政策/状态实例，保留原两站语义及测试，不能直接让新站绕过锁。普通目录解析失败可用旧目录，不伪造整个监控失败；服务器级限额仍共享。

## 字段与匹配语义

|来源字段|SeekBell语义|
|---|---|
|id|external_post_id，规范正整数文本，身份(v2ex,id)|
|title|标题，按正常长度/类型校验|
|member.username|可靠规则用户名；不使用last_reply_by或展示名替代|
|node.id|站内稳定类别值，作为字符串；不保存可变中文标题当条件|
|node.name/title|搜索slug/展示名及标签缓存|
|created|帖子发布时间，UTC；不以最后回复时间当新帖时间|
|content_rendered/content|仅列表随附内容转纯文本，最多2000字符；不另请求全文|
|replies|仅热榜可选展示，不参与监控身份或热度推算|

构造原帖https://www.v2ex.com/t/{id}，忽略#replyN及跟踪查询；API数字ID与链接ID冲突时跳过并留脱敏诊断，拒绝跨域/凭据/畸形URL。已见主题有回复/编辑不重推，首次有效采集只登记基线，重启保留Seen/Delivered账本；历史只保留首见快照，任务变更不重扫/补发。deleted标记的主题不推送；缺标题/合法ID等必需字段单条隔离，异常批次不能伪造成功。

摘要缺失与空文本区分，截断明确显示，关键词仅在已接收的标题/摘录中判断，不宣称全文。来源时间未知时不把最大created拼成更新时间，分别显示获取时间/帖子发布时间。含Linux DO的混合任务仍不能用共同精确作者条件，不能因V2EX有用户名就放开旧限制。

## 节点目录与任务UI

节点元数据以(website_id,node.id)持久化name/title/来源/最后确认时间，目录和最新主题提供的node共同补充，保留已选/已见但目录暂缺的旧节点，不能清空规则或变成全部。最新目录不等于匿名最新源覆盖保证。

复用已批准的按站摘要列表，V2EX行使用“全部节点/指定节点”，收起最多两个名称＋数量。千余目录不放进workspace全量响应；增加读取本地缓存的通用类别查询，按名称/slug/ID搜索并分页50条，搜索防抖、迟到响应隔离、已选跨页保留/单独可见、候选区限高、最多64项；输入搜索不直接请求V2EX。NodeSeek/Linux DO的小目录继续原交互，协议以能力声明区分inline/paged，不散落网站特判。

首次打开且无目录时只合并一次后台目录读取，忙碌可延期；loading/stale/failed/empty分开。离线仍可用成功目录及已选项，无目录时可以选全部并明确等待目录，不冒充“没有节点”。父子目录关系不隐式包含子节点；第一版按具体节点精确匹配，避免选择父节点扩大范围。

## 采集器、条件请求与热榜

不为此扩RSS解析器支持Atom。新增固定JSON主题采集器/纯V2exAdapter，沿用HTTPX/public_response和PostBatch，注册格式/端点/能力；SourceRunner及连接测试按适配器格式分发，不把JSON传parse_rss，也不在业务各处硬编码网站。RSS两站解析/HTTP2配置保持原语义。最多1MiB主题/热榜响应、目录单独2MiB上限及节点数上限，固定超时/MIME校验/XML策略不放宽，忽略用户简介、节点header/footer等无关HTML。

支持ETag/Last-Modified时仅在解析和入库事务成功后提交采集验证器；304记录“源未变化”，更新成功时间/计划，不写帖子/命中/队列、不重建基线或清空前窗口。首次空列表不应让后续第一批历史主题被当作新帖推送，保持未建立基线的明确状态。手测不保存采集验证器。遵守服务等待，不根据CDN长max-age停止正常采集。可新增独立源HTTP状态表而不重写现有来源数据，迁移/回退纳入验证。

热榜复用独立HotlistService与持久成功快照，首版仅“热门”一项并省去周期切换，保留官方响应顺序及原帖链接/用户名/节点/实际回复数；无浏览数不编造，无生成时间只显示获取时间。失败可显示带时间的旧快照，超过既有24小时期限诚实不可用，不用最新帖子或本地命中数冒充热度。
