# Linux DO 每周榜错开（v0.6.2，取代v0.6.1错峰）

日期：2026-11-08（Asia/Shanghai）。用户否定v0.6.1的错峰：热门、每日刷新要等几十秒，采集仍被挑战。用户给出方向：热门、每日照旧2秒间隔立即刷新，只把每周单独错开。

## 实机证据（现用实例，0.6.1 = 24a05e8，11/08 07:01只读）

- 近6小时没有`Hotlist refresh failed`日志；本机确认uvicorn日志配置下这条warning会输出。热榜请求本身没被挑战。
- linuxdo-rss采集345次，失败2次（01:34:47、06:52:44），都是access_challenge。只按每分钟1次采集时没有失败。
- 06:52序列：约06:51:43采集，06:52:07热门、:09每周、:22每日（用户切换标签，在看优先放行），:44采集被挑战。37秒内4个、61秒内5个，任何15秒内不超过2个。
- 结论：挑战大约按1分钟计数，“15秒2个”不够；挑战落在紧随热榜之后的采集上。结合11/04数据（3个热榜5秒间隔三轮都通过，第4个请求有被挑战），按每分钟最多3个Linux DO请求设计。

## 方案

1. 热门、每日到期即刷新，同站逐个、2秒间隔（恢复0.6.0节奏），加采集每分钟最多3个。
2. 每周榜（HotlistSource.staggered）须在热门、每日上次请求至少60秒后，且二者都不在接下来60秒内到期才刷新，无论选中哪个榜。
3. 去掉0.6.1的15秒计数、后台30秒间隔、在看/后台区分；保留切榜唤醒、失败日志、2倍间隔内失败不提示。
4. 单榜直接读取（get）不错开；从未获取的每周榜首次最多约等1分钟，显示加载。
