# 产品规格

## 1. 已确认定位与范围

个人自部署、单管理员、Web 管理、Docker Compose。首套环境为 PVE 的 Docker VM；用户表示无需额外讨论网络问题。支持反向代理，HTTPS 由外部代理处理；应用直接 HTTP 访问也可用。浏览器关闭不影响后台监控。

SeekBell定位为网站适配型监控工具，不专属于NodeSeek。首次部署不添加任何监控网站，管理员从内置网站库按需添加；同一内置网站只添加一次。首版可用适配器仅NodeSeek，使用官方 RSS https://rss.nodeseek.com/ 。不开放任意网站/任意 RSS 添加入口。网站与采集来源在模型中分离，但首版不展示未实现的多来源选项。

支持新帖标题、摘要、作者用户名、版块筛选；不宣称全文。没有回帖、帖子编辑提醒、TG 频道读取、网页抓取、用户账号采集、AI 分类、复杂摘要推送或第三方插件安装。

通知：Telegram Bot、Bark、邮件 SMTP、通用 Webhook。允许每类配置多个目标，任务可选择多个目标；目标单独启停、测试、记录投递结果。

## 2. 初始化与认证

首次访问创建管理员用户名和密码，不要求一次性初始化凭据。创建与初始化关闭必须原子化；重复/并发创建仅允许一个成功。后续不开放注册。重启/升级保留账号。

服务端会话、HttpOnly Cookie、CSRF 防护、密码安全哈希。反代 HTTPS 正确设置 Secure Cookie，仅信任明确配置的代理头；普通本地 HTTP 能完成登录。通知凭据加密、展示脱敏；恢复备份需包含/提供密钥。

## 3. 任务配置

一个任务对应一个监控目的，选择一个已添加的网站。已有任务固定所属网站；更换网站需新建任务，避免混用历史记录。有关联任务时先处理任务再移除网站；历史内容与投递留证。字段：

- 名称、启用状态、可选备注（最多160字符，随任务规则版本保存）。
- 版块多选；不限制即全部。
- 作者包含/排除列表；按原帖用户名精确匹配，不是搜索正文中的名字。当前没有稳定作者 ID，不保证改名后继续跟踪。
- 匹配范围：仅标题、仅摘要、标题＋摘要。
- 一个或多个条件组；每组有“全部包含”和“至少包含一个”。
- 整个任务的排除词。
- 默认不区分英文大小写，可开启；默认包含匹配；英文整词匹配作为可选模式。
- 一个或多个已配置通知目标。

组内各个非空条件都须满足；组间 OR；版块、作者和关键词结果之间 AND；排除词优先否决。空关键词允许只按作者/版块筛选；所有范围为空时明确提示将推送全部新帖。空条件组不能意外使其他条件组失效；服务端规范化/拒绝含糊结构。

例：组1全部包含 DMIT、任意包含 优惠/补货；组2全部包含 搬瓦工、任意包含 折扣/促销；任务排除 求购/已出。任一组满足且范围正确且无排除词才命中。

标题＋摘要时，各词可以分别出现在两字段；不允许把字段边界拼接出一个实际不存在的词。关键词按标签输入，短语保留内部空格。

摘要截断是已知范围限制：匹配和排除仅针对收到的摘要。摘要缺失与空文本需区分；有显式摘要要求而缺失时标记信息不足。对于标题＋摘要，已知字段可以证明阳性条件成立；缺失字段可能影响尚未确定的条件或排除词时，不误报为确定命中。用三值判断统一处理，规则说明和测试结果呈现原因。

首版不提供正则、自定义表达式执行、任意脚本。

## 4. 测试与历史语义

手动试匹配支持模拟输入字段；历史试匹配使用本地已有帖子，显示样本数量/时间范围和原因，不发通知、不改变去重状态。

第一次成功获取来源时，以当前条目建立基线，不推送已有帖子。来源首次请求失败，不误记初始化完成。

新建/修改任务仅对之后首次发现的帖子生效；不重新扫描历史并发送。基于稳定帖子标识与首次发现判断，不能仅凭 pubDate 或最大 ID 游标。

暂停/恢复不补发暂停期间帖子；保持共享采集记录才能判断暂停期间已见内容。网站级暂停恢复与程序意外停机区分：网站主动暂停默认恢复时重新建立当下基线；意外停机则处理仍可取得的未见条目并提示可能缺口。后两项为实施默认建议。

## 5. 去重与通知

内容键为 website_id + 原帖 ID。不要用标题、RSS 排序或发布时间去重。

每轮完成所有适用任务匹配后再按“原帖＋通知目标”合并。网页保留每个任务的命中记录；目标收到一条通知，列出相关命中任务。

相同帖子同一目标已成功接收后，不因重启、另一任务命中、内容更新或配置修改重复自动发送。不同目标独立记录；失败只重试失败目标。手动重发明确标记、单独记录。

不同配置默认是不同目标；能可靠识别指向同一接收端时提示重复，不能错误合并不同目标。不要用全局冷却代替帖子去重，避免压掉新帖子。

投递使用持久化状态、可恢复的工作租约、有限重试。平台已收到但响应丢失时可能重复，不承诺端到端 exactly-once。通用 Webhook 提供稳定事件 ID，便于接收端去重。

## 6. 页面

1. 概览：采集状态、最后成功时间、任务数量、命中/失败统计、异常。
2. 监控网站：已添加网站以适当大小的卡片列表展示，支持搜索/状态筛选；通过内置库按需添加。点击卡片打开详情与配置面板，包含能力、来源、连接测试、独立频率、启停、关联任务与移除。移动端使用全屏面板。新工作空间为空，不能显示假运行数据。
3. 监控任务：新建/编辑/复制/启停、条件组、自然语言说明、两类试匹配。
4. 内容与命中：本地帖子、筛选、原因、原帖入口。
5. 通知管理：目标配置与投递记录两个标签，测试/重试。
6. 系统设置：工作空间名称/说明、管理员、时区、保留策略、备份恢复、版本信息。工作空间名称1–24字符必填，说明最多40字符可选；保存同步侧栏，不改变管理员账号。

四种通知表单字段校验清晰；敏感字段不回传明文。外部内容默认文本安全展示，不执行 RSS HTML。

## 7. 实施默认建议（非全部逐项明确确认）

- 首版中文、手机浏览器可用；不做 App/PWA/浏览器推送。
- UTC 存储，浏览器时区初始化显示设置，可修改。
- 普通历史保留30天可调；独立精简去重记录不随普通历史自动删除。
- 通知统一模板：标题、原帖链接、作者、版块、时间、命中任务；摘要可开关/限长。Telegram 默认不展开链接预览，Bark 用短文本，Webhook 固定版本化 JSON。不做任意模板代码。
- 系统故障/恢复各通知一次，避免每轮刷屏；独立选择告警目标，全部渠道失败时网页仍可诊断。
- 暂停任务撤销该任务对未发送通知的贡献；其他启用任务仍命中则继续。修改规则不重写已生成通知快照。
- 禁用目标停止发送/重试；重新启用不自动倾倒积压旧消息，提供明确的手动重试。
- 删除任务保留可追踪历史并取消未发送贡献；在途请求无法保证撤回。
