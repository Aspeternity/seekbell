# 验收矩阵

状态初始全部“未执行”。每次记录：日期、提交SHA、镜像digest、环境、步骤、预期、实际、证据、是否用户验收。关键路径必须自动化；视觉与真实通知另做实机确认。

## 自动化必测

|ID|场景|预期|
|---|---|---|
|A01|首次并发创建管理员|仅一个账号成功，之后入口关闭|
|A02|登录、CSRF、退出、反代HTTPS与直接HTTP|各模式Cookie正确，未认证不能管理|
|R01|RSS包含完整字段/缺摘要/未知分类/非数字异常ID|合法条目正确映射；异常可诊断，不使整批静默丢失|
|R02|首次抓取失败后成功|成功时才建立基线，旧条目不推送|
|R03|重复、乱序、同名不同ID、不同网站同ID|按规范身份去重；新帖不被误删|
|R04|HTTP错误/429/HTML挑战页/坏XML|退避并显示失败，不误记正常空源|
|R05|前后采集集合无交集|提示可能缺口，不声称精确漏帖数量|
|F01|条件组AND/OR/排除/空规则|与页面解释完全一致|
|F02|大小写、中文短语、英文整词|按配置匹配，空格不破坏短语|
|F03|标题与摘要分布、边界拼词、摘要缺失|不跨字段造词；信息不足不误判|
|F04|作者/版块过滤|按原帖字段；未知字段不假装匹配|
|F05|手动/历史试匹配|不发送、不修改已见/已发状态|
|D01|两任务同帖同目标、另一目标|每目标一条；各任务命中仍可查询|
|D02|通知HTTP200但业务失败、超时、永久错误|正确分类、有限重试；永久错误不无限重试|
|D03|一个目标成功一个失败|仅重试失败目标|
|D04|事务前/后崩溃、认领后崩溃|无已处理但无投递意图的空洞；租约可恢复|
|D05|远端接收后本地超时|记录不确定性，不伪称exactly-once|
|D06|暂停/删除任务、禁用目标、规则修改|符合规格的未发送贡献/快照语义|
|D07|手动重发|明确独立记录，不重置自动去重|
|P01|清理历史后同帖再次出现|不重新推送|
|P02|备份恢复含加密凭据|账号、规则、已见/已发、密钥均可恢复|
|P03|升级迁移失败与回退|失败安全停止，可恢复匹配的数据版本|
|S01|恶意标题HTML、外部URL、日志敏感数据|不执行脚本，无凭据泄漏|

## 实机检查

1. 在 PVE Docker VM 启动固定SHA镜像，记录版本，创建管理员。
2. 反代HTTPS登录、刷新、退出正常；重启不回初始化页面。
3. 官方RSS真实连接成功，页面显示最近成功时间、20条窗口限制提示（实际数量动态展示，不能写死为20）。
4. 四种渠道各使用授权目标发送测试，确认手机/客户端实际收到，链接可点击；SMTP记录接受状态和用户确认分别填写。
5. 创建两条命中同一帖子且同目标的任务，使用受控测试环境验证合并；真实论坛不为测试发帖。
6. 验证手机页面的任务编辑、规则解释、错误提示。
7. 更新镜像/重启保留账号、任务、凭据、去重和待投递任务。
8. 测试环境模拟通知失败，观察重试/最终失败/手动处理。
9. 恢复备份至独立数据目录，禁止覆盖日常环境作为试验。
10. 记录真实RSS在所选频率下的稳定性；不能把短时成功视为官方许可或长期可靠性保证。

CI不调用真实通知、不轮询论坛。仅 amd64 实机通过时，如实标记 arm64 未实机验证。
