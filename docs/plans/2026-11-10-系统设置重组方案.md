### 1.2 功能缺口

1. **恢复留下的旧数据看不到也删不掉。** 每次网页恢复都会在数据目录新建一个`before-restore-…`目录保存整份旧库（`backups.py:321`），代码里没有任何清理；存储统计只算`web-restore`（`maintenance.py:74-90`），所以这部分占用在界面上不可见。
2. **旧的“恢复副本”是遗留功能。** 界面仍保留删除`web-restore`副本的表单（`BackupSettings.vue:263-313`），但生成该副本的`/backups/restore`接口前端已无任何调用。
3. **告警无法验证。** 没有“发送测试告警”，配好后只能等真实故障。
4. **告警无防抖。** 每次故障/恢复切换立即入队发送（`alerts.py:30-81`）；而运行中心把1分钟内自动恢复的问题默认视为噪音隐藏，两处口径矛盾。
5. **告警可勾选未配置的目标**，保存时才被后端拒绝（`AlertsSettings.vue:158`对比`alerts.py:108-115`）。
6. **登录固定12小时且不续期**（`authentication.py:16,89`），自托管场景每天要登录两次。

### 1.3 代码问题

1. 通用、概览、告警、保留四页各自重复约60行“读取/应用/重读/放弃/保存/dirty/卸载保护”状态机，且已出现漂移：告警与保留的`load`失败分支不检查组件是否已卸载，状态文案和`watch`选项不一致。
2. `Settings.vue`内联了整个账户表单（约130行），其他分类都是独立组件；`sessionDirty`只写不读（43、77、232行），会话卡发出的dirty被丢弃；dirty按标签名用三元表达式分流并共用一个`auxiliaryDirty`。
3. 合法标签列表在`App.vue:105`与`Settings.vue:14`各写一份。
4. 无调用方的代码：`store.ts:382 savePreferences`及其唯一使用的`PUT /manage/workspace`；`GET/PUT /manage/display`；`/manage/alerts/state`、`/alerts/history`、`/alerts/history/{key}`（运行中心改用问题历史后）；`POST /manage/backups/restore`。后端测试仍引用其中一部分，删除时需同步调整。
5. `GET /manage/workspace`返回的`retention`、`alertTargets`、`recoveryAlerts`除设置页自己回写外无人读取，而设置页另有专用接口。
6. 字节大小格式化写了三份（`AboutSettings.vue:50`、`StorageSummary.vue`、`BackupSettings.vue:60`）；`formatTime(new Date(x * 1000).toISOString())`重复多处。
7. 设置接口散落在648行的`management.py`（与网站/任务/目标/规则/运行状态混在一起），概览布局接口在`hotlists.py`；`general_view`在函数体内导入。

## 2. 重组方案

### 2.1 七类并为五类（仍用顶部横向标签）

| 新标签 | 内容 | 来源 |
| --- | --- | --- |
| 通用 | 工作空间、时间显示、概览布局 | 通用 + 概览 |
| 告警 | 开关、接收目标、测试发送 | 系统告警 |
| 数据 | 历史保留、存储占用、备份与恢复、操作记录 | 历史与存储 + 备份与恢复 |
| 账户 | 用户名、修改密码、登录会话 | 账户与安全 |
| 关于 | 不变（11-08刚确认） | 关于 |

五个两字标签在360px宽度下不需滚动。旧地址全部重定向：`/settings/overview`→通用的概览布局区块，`/settings/retention`、`/settings/backup`→数据页对应区块。

### 2.2 各页调整

**通用**：三个区块同页。工作空间与时区仍一次原子保存；概览布局因是独立资源保留独立保存，但共用同一种保存栏。

**告警**：单卡。去掉“每次保存都确认”，仅在关闭告警（会取消待发）时确认；目标列表中未配置的目标置灰并注明原因；发送规则继续折叠。

**数据**：
- 历史保留压成一个区块：天数 + 预览清理影响 + 折叠的“最近一批清理”。
- 存储占用只保留这一处明细；关于页继续显示概况，但两处改用同一口径和同一格式化函数。
- 备份下载/恢复沿用现有表单与口令规则；操作记录收为卡内折叠列表。

**账户**：拆成“用户名”和“修改密码”两个小表单，各自要求当前密码；“退出登录”与“退出其他会话”一起放进登录会话卡，表单底部不再放退出链接。

**统一保存反馈**：所有可编辑页用同一个保存栏组件，无修改时不占显眼位置；校验错误不再出现“重新加载”按钮，只有读取失败和版本冲突才出现。

### 2.3 功能补强（每项单独确认，均会改变行为）

| 编号 | 内容 | 影响 |

| C2 | 告警页“发送测试告警”，向所选目标各发一条标明为测试的消息 | 属真实发送，仅用户点击时触发；CI用模拟目标 |

## 4.1 功能取舍结论（2026-11-10补充，待用户确认）

更正：`web-restore`验证副本流程按`BACKUP_RESTORE.md:33`仍留给维护工具使用，`/backups/restore`不删；C1改为把它与`before-restore-…`合并成一个“服务器上的恢复残留”列表统一查看和删除。

**建议加**：恢复残留查看与删除（C1）；发送测试告警（C2）；磁盘空间不足告警（现有故障来源只有采集、投递、后台三类，磁盘写满无任何提示）；告警延迟（C3）；保持登录（C4）；定时自动备份（价值最高，但要先定口令如何保存，单独立项）。

**建议删或并**：导航外观预览；WAL单独一格（并入数据库大小）；后台清理的“后台状态/下次检查”（运行中心已有）；账户表单里的退出链接；“当前会话到期”（未做C4时恒为登录后12小时）；标题旁“单管理员”徽标；1.3第4条中除`/backups/restore`外的无调用接口。

**建议改**：告警保存确认、未配置目标可勾选、账户表单拆分、历史保留压缩为一个区块、存储口径统一、校验错误的“重新加载”按钮、“查看告警记录”改名为“查看问题历史”。

**不建议做**：手动“立即清理”、数据库压缩按钮、按数据类型分别设保留天数、告警按类别订阅、两步验证、在线检查更新、主题与阅读密度。
