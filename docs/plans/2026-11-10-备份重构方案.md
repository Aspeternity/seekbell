# 备份重构方案（2026-11-10，第二稿，待用户审批）

基准：main `85618ba`（v0.8.0）加未提交的系统设置重组。本文只是方案，未改代码。审批后，稳定需求回写SPEC，架构写进ARCHITECTURE/DECISIONS，操作流程写进BACKUP_RESTORE。

用户已定（11-10）：
- 项目尚未正式使用，现有备份都是测试数据，**不兼容旧格式**。
- 备份**不加密**（选项A），不设备份口令或密钥。

## 1. 现状与问题

| 现状 | 问题 |
| --- | --- |
| 每次下载都要手设备份口令（≥12字符、输两遍），加密后下载 | 口令一忘，备份就废了；操作繁琐；服务器拿不到口令，做不了定时备份 |
| 服务器上不保存任何备份，只能手动下载 | “上次什么时候备份的”藏在操作记录折叠里；升级前备份全靠人记得 |
| 下载用`fetch`取成Blob再存盘 | 整份备份（最大2 GiB）先占浏览器内存，没有进度 |
| 恢复直接上传后替换 | 恢复前看不到备份里有什么，选错文件要等替换完才知道 |
| 恢复前的旧数据留在`before-restore-*`目录（即“恢复残留”） | 只能删不能回退；它和“备份”是两套概念 |
| 备份失败、长期没备份 | 运行中心和系统告警都没有任何提示 |

## 2. 为什么不加密，以及怎样补足安全

- 加密要成立，就得有一把不随文件走的钥匙。钥匙只放在服务器上，服务器坏了备份就打不开；钥匙跟着文件走，又等于没加密。为了“不用保管任何东西”，选择不加密。
- 服务器上的数据（数据库、凭据主密钥）本来就没有加密，所以**服务器本地的备份加不加密，安全性都一样**。风险只在离开服务器的文件上。
- 多数自托管工具（Uptime Kuma、Gitea等）的备份也不加密。

**补足措施：**
1. **备份里不放管理员密码哈希和登录会话。** 恢复时，管理员一律由恢复方决定：就地恢复保留当前管理员；新安装恢复时在页面上设置；命令行恢复时交互输入。这样文件泄露也拿不到可以离线破解的密码。
2. 服务器上的备份文件权限0600，目录0700，与数据同等保护。
3. 下载、删除和恢复都要验证管理员密码（沿用15分钟内免输）。
4. 下载和备份页明确提示：“文件包含通知渠道的凭据（TG Bot Token、SMTP密码等），请像保管密码一样保管，不要放到公开位置。”
5. BACKUP_RESTORE写明泄露后的处置：到各平台重置Token和密码，再在SeekBell里更新通知目标。

以后真有人要把备份放到网盘，可以再加一个“下载时额外加密”的可选项。默认不开，本方案不做。

## 3. 目标设计

### 3.1 备份文件格式

- 标准`tar.gz`，文件名如`seekbell-20261110-030000-auto.tar.gz`，里面只有三个固定文件：
  - `manifest.json`：格式版本、应用版本、数据库结构版本、构建版本、创建时间、来源类型、各文件大小与SHA-256，以及内容摘要（工作空间名，网站、任务、通知目标、内容条数）。
  - `seekbell.sqlite3`：用SQLite备份机制取得的一致快照，并删除管理员和登录会话。
  - `credentials.key`
- 用标准格式，是为了出问题时可以用`tar`手工解开、放回数据目录，不依赖SeekBell界面。
- 读取时严格防护：只接受这三个文件名、只接受普通文件；解压后的大小有上限（数据库2 GiB），防压缩炸弹；逐个核对SHA-256；然后沿用现有的结构、完整性、外键和凭据校验。
- 旧的`.sbbackup`加密格式不再支持，上传时提示“旧格式测试备份已不支持”。

### 3.2 服务器端备份库

- 默认存`/data/backups/`。可选环境变量`SEEKBELL_BACKUP_DIR`，挂载另一块盘或NAS目录（compose与Portainer模板里给出注释示例）。备份和数据在同一个文件系统上时，界面提示“磁盘损坏会一起丢失，请定期下载或挂载独立备份目录”。
- 以目录为准：启动和列表时扫描，元数据缓存在数据库。手动放进去的备份文件也会列出，可以恢复或删除。
- 四种来源：**手动**、**自动**、**恢复前**（恢复时自动生成，取代“恢复残留”）、**升级前**（第三期）。
- 保留规则：自动备份保留N份（默认7）；恢复前和升级前备份保留30天，但每种最新的一份不删；手动备份不自动删除。
- 备份计入存储占用。生成前先检查空间，可用空间不足数据库2倍时直接失败并说明原因。同一时间只运行一个备份或恢复（沿用现有门禁）。

### 3.3 自动备份

- 每天或每周，按显示时区的时刻运行（默认每天03:00），在进程内运行，与历史清理相同。错过的（比如容器关着）启动后补做一次。
- 失败时产生一条“备份”故障，进运行中心和系统告警，下次成功后恢复。超过2个周期没有成功备份，也产生一条故障。
- **默认开启**：本机多留几份，主要防误操作，也让恢复可以回退。

### 3.4 恢复

统一成一个三步向导，系统设置和初始化页共用：
1. **选择来源**：备份列表里某一份的“恢复”，或上传文件（拖放，显示上传进度）。
2. **检查**：服务器校验文件，**不替换任何数据**，然后显示备份时间、来源工作空间、版本（“会自动升级”或“版本过新，不能恢复”），以及内容条数与当前的对比。上传的文件暂存在私有目录，30分钟内不再确认就清理，确认时不用重新上传。
3. **确认**：“恢复后暂停采集和通知”（默认勾选），按需输入当前管理员密码，并说明“恢复前会先自动备份当前数据，可随时从列表回退”。初始化页这一步改为设置管理员用户名和密码。

替换机制沿用现有做法（停止接受请求、等待在途请求、整份换入，失败时换回）。区别只有一点：替换前先生成一份“恢复前”备份；成功后删除换下来的目录，不再留下`before-restore-*`。恢复后管理员按上面的规则设置，旧会话全部失效，发起恢复的浏览器直接获得新会话。

### 3.5 下载

列表里的“下载”改用普通的GET流式下载：浏览器直接写盘，显示原生进度，不占内存。先用POST换一张只能用一次、60秒有效、绑定当前会话的票据（这一步按需验证管理员密码），再用票据跳转下载，不暴露可以免认证访问的地址。所有响应都设`no-store`。

### 3.6 命令行

`python -m seekbell.backup create`（停服后运行）直接生成同格式文件，不再询问口令。`restore`恢复到一个新目录，交互设置管理员。两者都不再要求交互终端输入口令。

## 4. 界面

备份标签从上到下：

```
┌ 备份状态 ────────────────────────────────────────────┐
│ ● 已保护　上次备份 今天 03:00（自动）· 下次 明天 03:00      │
│ 存放：/data/backups · 7 份 · 共 12.4 MiB · 磁盘可用 41 GiB │
│ ⚠ 备份与数据在同一磁盘……（同盘时显示）                     │
│ 备份文件包含通知渠道的凭据，下载后请妥善保管                 │
│                          [从文件恢复…]  [立即备份]          │
├ 备份列表 ────────────────────────────────────────────┤
│ 时间            类型    大小      版本    内容            │
│ 11-10 03:00    自动    1.8 MiB  0.9.0  2站·5任务·3目标 ⋯ │
│ 11-09 21:14    恢复前  1.7 MiB  0.9.0  …               ⋯ │
│ 11-08 10:02    手动    1.7 MiB  0.9.0  …               ⋯ │
│ （⋯ 菜单：下载 / 恢复 / 删除；手机上每行改成卡片）          │
├ 自动备份 ────────────────────────────────────────────┤
│ [开] 每天 ▾ 03:00 ▾　自动备份保留 7 份                     │
│ 恢复前、升级前备份保留 30 天；手动备份不自动删除            │
│                              （统一保存栏 SettingsSaveBar）│
└────────────────────────────────────────────────────┘
```

- 状态卡把最重要的事放第一眼：现在有没有可用的备份。状态有三种：绿（已保护）、橙（备份失败，或超过2个周期没有备份）、灰（还没有任何备份）。
- 删除切换按钮和“操作记录”卡：列表本身就是记录。恢复、删除另记审计记录，在列表下方折叠显示最近若干条。
- “恢复残留”卡取消，改为列表里的“恢复前”条目。数据页存储占用的“恢复残留”格改为“备份 N 份 · 大小”。现有的`before-restore-*`和`web-restore`都是测试遗留，升级时直接删除，不再保留任何界面。
- 恢复向导用抽屉（手机全屏），三步有进度指示，每一步都可以返回或取消。
- 初始化页“已有备份？从备份恢复”走同一个向导：上传文件，预览，设置管理员。

## 5. 接口

| 接口 | 说明 |
| --- | --- |
| `GET /manage/backups` | 状态、计划、列表、审计记录 |
| `POST /manage/backups` | 立即备份 |
| `DELETE /manage/backups/{id}` | 删除（验证管理员密码，15分钟免输） |
| `POST /manage/backups/{id}/ticket`、`GET …/file?ticket=` | 流式下载 |
| `PUT /manage/backups/schedule` | 自动备份设置（带revision冲突检查） |
| `POST /manage/backups/inspect` | 上传文件或选择列表项，检查后返回暂存ID与摘要 |
| `POST /manage/backups/inspect/{stage}/restore` | 确认恢复 |
| `/auth/setup/inspect`、`/auth/setup/restore` | 初始化页对应接口 |

删除旧的`/download`、`/apply`、`/restore`（验证副本）和`/leftovers`接口；维护工具中启用`web-restore`副本的流程同步删除，改为“用命令行把备份恢复到新卷，再切换”。迁移0020：备份计划单例、备份元数据缓存、审计记录，并替换现有`backup_records`。

## 7. 不做

加密与口令（以后按需加“下载时额外加密”可选项）；云端或WebDAV/S3上传（属于外发网络，超出首版范围，只支持挂载目录）；只恢复部分数据（数据之间有依赖，容易不一致）；增量或去重备份（库的大小用不上）。
